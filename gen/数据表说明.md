## 2. sigils.xlsx / sigils-full.xlsx 字段（14 列）

| 列 | 字段 | 原字段名 | 说明 |
|---|---|---|---|
| A | key | Key | 因子逻辑名（`GEEN_xxx`，或 hash 形态——新 DLC/星海等）|
| B | hash | Hash | gem hash（=hash-string(key)）——**因子身份唯一值**；技能条目=技能 hash |
| C | name | Name | **英文名**（en\text.msg）|
| D | zh | Zh | **中文名**（cs\text.msg）|
| E | skill1 | SkillId1 | 主技能 hash（=hash-string(SKILL_xxx)）；**技能条目=自身 hash** |
| F | skill2 | SkillId2 | 副技能 hash（多为空）|
| G | player | PlayerReq | 角色 PL 码（`PL0300` 等）；专属因子非空，非专属空 |
| H | lot | SkillTypeLotIdForRandom2ndSkill | **随机第 2 技能池展开 = 技能 hash 列表**（空格分隔）。**仅 9 个池版因子**（mix=1 & player="" & one=0 & skill2="" 且 lot≠-1）有值：lot=6→38 项、7→16 项、16→72 项；其余行（可合成员/固定副/专属）为空 |
| I | category | Category | 类别 1-5（1 基础数值/2 能力延伸/3 防御/4 回复/5 特殊）|
| J | rarity | Rarity | 稀有度 1-5 |
| K | mix | CanGemMix | **合成资格**：0=可作素材（任意组合，不查池/类别）；1=锁定（专属/活动/顶格，不可放台，副技能只来自自身 lot 池）——实测+全量验证 |
| L | one | CanOnlyHoldOne | 唯一持有（现表 5 行）|
| M | cap | cap | 技能等级上限（公式见 §4）|
| N | character | character | 角色 hash（=hash-string(player)；专属行有值，非专属空）|

**C++ 加载器行格式契约**（`name_tables.cpp`，改动需同步）：`sigils.json` 每字段独占一行；`"hash"` 与 `"character"` 必须落在同一对象内；对象以单独成行、内容恰为 `},` 或 `}` 的一行结束。字段顺序与额外字段（如 `lot`）不限。

**识别公式**：`hash == skill1` → **非物品技能**（12 条）；否则 → 因子物品。误判不可能（因子行 hash=gem ≠ skill1）。

## 3. 关键机制

1. **表内是逻辑键，hash 由 GBFRDataTools 词典翻译**：词典有词→明文；无词（DLC/新内容）→保留 hash。所有 hash 可用 `hash-string` 复算还原逻辑名（如 70051799=GEEN_147_34、BF78FBFC=SKILL_301_00、8B8085C0=GEEN_320_24）。**同名多 hash 取首条**：词典对少数名字给多条（如 `PL2800` = 646C3168 / 80E0DE61），首条是游戏规范 id（原生角色表用的就是它）——`xlsx-lib.readIds()` 按此实现。
2. **合成系统**（万事屋谢洛·因子合成）：两素材 → 新因子；结果=素材 4 技能的 12 种两两组合（无配对限制表）；素材资格=`mix=0`；费用/等级=`gem_mix_rupi/ticket`（CombinedLevel=素材 Lv×2 等）。**与炼成（gem_mix 配方/材料）是两个系统**。
3. **副技能池（lot 正确提取：双层展开）**：`lot` 值（2/3/4/5/6/7/15/16/26/27）→ `skill_type_lot` 行（子池 Key+概率）→ **每个子池 Key 在 `skill_lot` 对应 3~22 个技能**（`skill_lot` 是 Key→多技能，需逐个展开）→ 合并去重=最终列表（lot6=38、lot7=16、lot16=72）。**lot 只分配给池版因子**（mix=1 & player="" & one=0 & skill2="" 且 lot≠-1，仅 9 个；形状符合但 lot=-1 的 2 行清空：GEEN_103_04 全弱化效果抗性、GEEN_044_04 霸体）；其余行 lot 空（可合成自由组合，无需池）。设计规则：**选择池版因子时，副因子必须落入其 lot ∪ 族固定副(sec)，否则非法（灰显/红字提示，不阻止保存）**。
4. **活/死条目**：产出池（`reward_lot.GemId` + `gacha_lot.ItemId`）外部引用 **>0 = 活，=0 = 死**（`_34` 版全部零引用）。
5. **展示等级 "1+N"**：技能表 `max(Level)` = N（表驱动）。属转/狂战士/斯巴达=15 级表；漆黑钳蟹=20 级表；相扑=5 级表；霸体=单级表（023）+基础版表 15（044_00）。

## 4. cap 公式（全表驱动，零特判）

```
1. 组内主技能（skill1）等级表 max(Level) ≥ 2 → cap = 该值
2. 单级表 / 无表 → cap = 15（因子 R5 上限，对应"1+15"显示）
```
> 组=同名组（基础名，去罗马/＋）；`skill_status` 键双形态（明文+hash）均已归一；技能条目 cap 同公式。

## 5. 生成管道（按序执行）

```powershell
$S = gen        # 脚本目录（本仓库；以下命令以本仓库根为当前目录）
$D = gen        # 数据目录（本仓库内：解包/词典/中间产物，gitignored）

# ① 解包 → SQLite（gbfr.db=管线标准输出；gbfr4.db=41 表全量，池/引用数据取自它）
GBFRDataTools extract -i <data.i> -f <tbl> -o $D\extracted
GBFRDataTools tbl-to-sqlite -i $D\extracted\system\table -o $D\gbfr.db -v 2.0.5
GBFRDataTools tbl-to-sqlite -i $D\extracted\system\table -o $D\gbfr4.db -v 2.0.5
# ② 输入 CSV / JSON（sqlite3 直写文件，勿用 PowerShell 重定向）
sqlite3 $D\gbfr.db  ".mode csv" ".headers on" ".output $D\gem-all.csv"   "select Key, Name, SkillId1, SkillId2, PlayerReq, IsLuciliusGem, SkillTypeLotIdForRandom2ndSkill, Category, Rarity, CanGemMix, CanOnlyHoldOne from gem"
sqlite3 $D\gbfr.db  ".mode csv" ".headers on" ".output $D\cap.csv"       "select Key, max(Level) from skill_status group by Key"
sqlite3 $D\gbfr.db  ".mode csv" ".headers on" ".output $D\skillnames.csv" "select Key, Name from skill"
sqlite3 $D\gbfr4.db ".mode csv" ".headers on" ".output $D\skill_type_lot.csv" "select * from skill_type_lot"
sqlite3 $D\gbfr4.db ".mode csv" ".headers on" ".output $D\skill_lot.csv"      "select * from skill_lot"
sqlite3 $D\gbfr4.db ".mode csv" ".headers on" ".output $D\reward_lot.csv"     "select * from reward_lot"
sqlite3 $D\gbfr4.db ".mode csv" ".headers on" ".output $D\gacha_lot.csv"      "select * from gacha_lot"
node $S\parse-msg.js $D\extracted\system\table\text\en $D\en.json
# ③ 池映射 / 保留名单 / 基础 CSV
node $S\build-lotmap.js  $D\skill_type_lot.csv $D\skill_lot.csv $D\GBFRDataTools\Data\ids.txt $D\lotmap.json
node $S\build-gem-csv.js $D\gem-all.csv $D\extracted\system\table\text\cs $D\GBFRDataTools\Data\ids.txt $D\gem-full.csv
node $S\build-keepmap.js $D\gem-full.csv $D\GBFRDataTools\Data\ids.txt $D\lotmap.json $D\reward_lot.csv $D\gacha_lot.csv $D\keepmap.json
# ④ CSV 规则：一次过完成 ①同名去重 ②剔除空名 ③剔除名单
node $S\filter1.js $D\gem-full.csv $D\filter1.csv $D\keepmap.json    # 1034 → 375 → 360
# ⑤ CSV → xlsx 部件（自带 sharedStrings，后续脚本可直接读）
node $S\make-xlsx.js $D\filter1.csv $D\parts
# ⑥ xlsx 规则（均"解包→改→打包"，按删除量从大到小）
node $S\filter-groups.js $D\parts $D\keepmap.json                    # 360 → 246 → 244
node $S\filter-drop.js   $D\parts $D\keepmap.json                    # 244 → 216 → 191
# ⑦ 派生与列变换
node $S\replace-skills.js $D\parts $D\GBFRDataTools\Data\ids.txt
node $S\add-lot.js       $D\parts $D\lotmap.json
node $S\build-capmap.js  $D\gem-all.csv $D\cap.csv $D\capmap.json
node $S\add-cap.js       $D\parts $D\GBFRDataTools\Data\ids.txt $D\cap.csv $D\capmap.json
node $S\add-skills.js    $D\parts
node $S\add-zh.js        $D\parts $D\en.json $D\gem-all.csv $D\skillnames.csv
node $S\rename-headers.js $D\parts
node $S\style-xlsx.js   $D\parts                                    # 行底色：lot/player/one/技能条目
# ⑧ 产物
node $S\make-sigils-json.js $D\parts GBFR.PreEquippedSigils\sigils.json   # mod 运行时数据（也可直接吃 .xlsx，见下）
# sigils.xlsx = $D\parts 直接压缩为 zip（文件名 sigils.xlsx）

# ⑨ 全量对照表（1034 条原始行；列名/取值与 ⑧ 同格式，便于直接从全量行转换）
#    与 ⑥⑦ 同一批变换，只是不做 filter-groups/filter-drop、不追加 add-skills
node $S\make-xlsx.js      $D\gem-full.csv $D\parts-full
node $S\replace-skills.js $D\parts-full $D\GBFRDataTools\Data\ids.txt
node $S\add-lot.js        $D\parts-full $D\lotmap.json
node $S\add-cap.js        $D\parts-full $D\GBFRDataTools\Data\ids.txt $D\cap.csv $D\capmap.json
node $S\add-zh.js         $D\parts-full $D\en.json $D\gem-all.csv $D\skillnames.csv
node $S\rename-headers.js $D\parts-full
# sigils-full.xlsx = $D\parts-full 直接压缩为 zip
```

> `sigils.json` 的 `name`/`zh` 用**技能基础名**：sigils.xlsx 保留因子名的 `＋`/罗马数字后缀，生成 json 时去掉（`zh` 去 `＋` 与中文罗马数字；`name` 再去英文罗马数字）。

> 脚本共用 `gen\xlsx-lib.js`（xlsx 行解析/写回、sharedStrings 写入、CSV 读写）；行解析是标签感知扫描，单元格文本里的字面 `</row>` 不会再截断行。

> **局部重跑（不必重建数据源）**：
> - sigils.json：`node gen\make-sigils-json.js gen\extracted\sigils.xlsx GBFR.PreEquippedSigils\sigils.json`
>   （脚本直接吃 .xlsx 或部件目录；加 `--check` 只比对不写文件，供构建门禁使用）
> - 专属表：`pwsh docs\tool-gen-loadout.ps1`（写 `character-exclusives.json` + `template_loadout.cpp` 表段；`-Check` 只比对）
> - `build-release.ps1` 构建前自动比对上面两组产物与数据源，不一致直接报错；数据目录 gitignored，新克隆没有 `extracted/` 时自动跳过。

## 6. 筛选级联（按执行顺序）

每级内部按删除量从大到小；级间顺序已实测无影响（见下）。

| 级 | 规则 | 判据 | 删除 | 脚本 |
|---|---|---|---|---|
| ① | 同名去重 | 同名组：最高 Rarity → plus 优先 → 平级全保留（keepmap 例外放行） | −659 | `filter1.js` |
| ① | 剔除 Name 空行 | 文本键不存在 = 隐藏因子 | −11 | `filter1.js` |
| ① | 剔除名单行 | 7net、幸运甘露、修炼甘露、强健甘露（活动/联动，不参与配装） | −4 | `filter1.js` |
| ② | 同名组去固定副 | 组内只留 `skill2` 空；组内全为有副版则整组保留 | −114 | `filter-groups.js` |
| ② | 同名组去 lot=−1 | 组内只留 `lot≠-1`；组内全 −1 则整组保留 | −2 | `filter-groups.js` |
| ③ | 行级剔除：觉醒 | `player 非空 & one=1`（`_90`） | −28 | `filter-drop.js` |
| ③ | 行级剔除：死条目 | 21 个 hash + 3 个明文 `_34`（产出池零引用）＋ keepmap.drop | −25 | `filter-drop.js` |

**数量链**：1034 → 375 → 360 → 246 → 244 → 216 → 191 →（追加 12 条技能）203

**顺序无关（实测）**：12 种排列（F3/F4 互换、F6/F8 前置、完全逆序等）最终都是同样的 191 行——同名组两级与行级两级都收敛到同一结果。

**条件例外（keepmap）**：由 `build-keepmap.js` 从「产出池引用 + 同族 lot 池」算出，非硬编码。

- **keep 4**：被产出池引用、且副技能不在同族 lot 池内的固定副——`05FE0351`（斯巴达＋体力）、`6EFCD286`（属转＋协同攻击）、`6FF3308A`（属转＋分歧）；外加 `GEEN_044_04`（霸体基础版）。
- **drop 1**：`GEEN_044_24`（霸体＋，零引用）。同组恰为 {`_04`,`_24`} 两行且 `_04` 被引用 → 换回 `044_04`。**必须与同名去重合看**：plus 优先会先删掉非 plus 的 `044_04`，再由这一条换回，否则会误判成"删错"。
- **反例**：凝神 `3D0BF8CB`、追击 `GEEN_151_94` 虽被引用，但副技能在同族池内 → 照删；`CE8C3C96` 池外但零引用 → 照删。
